# 雀魂牌局观察器：核对原型

Edge Manifest V3 扩展。只在 `https://game.maj-soul.com/*` 页面采集，无第三方运行依赖或遥测。当前版本为 **0.2.0**，支持用户自选大模型服务；分析默认关闭，仅手动点击时发送所选数据。协议字段尚待当前客户端实测。

## 本局结果与整场记录

收到结算后，面板显示“本局结果”：自摸、荣和、荒牌流局或途中流局，以及各家最终点数和相对开局的净变化（含立直扣点）。番符仅在消息提供时显示；点数缺失时保持未知，若收到下一局开局点数则补齐上一局。

展开面板顶部的“整场记录”，选择场次，点击某局的“查看”，可回看该局结算时的手牌、牌河、副露、宝牌和结果；本场数分别保留，连庄不会覆盖前一局。查看旧局时后台继续采集，点击“返回当前牌局”即可恢复当前画面。打开完整牌谱时也会按局整理记录，重复打开相同牌谱会去重，插件的牌谱游标不受影响。

记录保存在当前浏览器扩展本地，刷新后仍可查看；最多保留最近20场、每场100局，并按约4MiB总量淘汰最旧场次。保存的是结算快照，不含逐事件回放。未采集到的旧局无法自动补回；漏掉结算时会标注“结果未采集”。当前刷新或断线后继续采集同一场可能被分为不同场次，尚不保证自动续接。导出核对JSON包含已加载的历史记录，可用于备份。

## 大模型分析

1. 重新加载扩展并刷新游戏，在面板找到“模型分析 → 模型设置”。也可从扩展管理页打开扩展选项。
2. 开启模型分析，填写 **OpenAI Chat Completions 兼容接口的完整地址**、模型 ID 和 API Key。例如 `https://api.openai.com/v1/chat/completions`；第三方服务请填写该服务的地址和模型名。支持 `http://localhost:端口/v1/chat/completions`、`http://127.0.0.1:端口/v1/chat/completions` 本地服务，本地服务无密钥时可留空。
3. 点击“保存设置”，授予该服务主机的访问权限。扩展不默认申请所有网站访问权；浏览器主机授权覆盖同主机的端口，实际请求只发送到配置的完整地址。
4. 返回游戏，状态会在页面获得焦点时刷新；也可点击“刷新设置状态”。选择发送“对局信息”、全部或某一家牌河，以及是否发送自家手牌。自家手牌默认不勾选；先确认自家座位，牌谱模式需手动选择。
5. 选择“危险牌”“建议打的牌”或两者，展开“预览发送数据”核对，再点击“发送所选数据并分析”。结果在插件内显示；局面、模式、游标或发送范围变化后，旧结果明确标记为已变化。

开启不代表持续上传。每次分析只发送点击时的当前快照，不发送完整事件历史、账号、会话、牌山或对手暗牌；即使牌谱中已有四家手牌，也只发送所选自家手牌。对局信息包含点数、局数、宝牌、副露、立直状态等，牌河与自家手牌独立选择。

API Key 仅保存在当前浏览器的扩展本地存储，不参与同步或导出，局面页面只能查询开关和模型名称；密钥只由扩展后台添加到目标服务请求。服务商将收到所选数据，可能按其规则收费。可在设置页随时关闭分析或清除配置和密钥，变更配置会取消进行中的请求。已发出的数据无法撤回，取消不保证服务商停止计费。

当前支持非流式 `POST /chat/completions` 和 `choices[0].message.content` 文本响应，不支持原生 Anthropic、Gemini 或 Responses API；可通过兼容网关接入。请求25秒超时、单标签页同时一个请求；接口重定向会被拒绝。模型输出以纯文本显示，仅供参考，不代为出牌；数据缺失时会提示，建议质量取决于模型与采集准确性。

项目分层、数据流与模块职责见 [ARCHITECTURE.md](ARCHITECTURE.md)。

手牌、牌河、副露、宝牌及事件列表使用本地牌面图片，包含34种常规牌与3种赤五；悬停可看牌名。未知牌显示问号，避免与白板混淆。图片随扩展打包，不向外部图床请求。

“宝牌指示牌”下方显示计算后的“宝牌”：数牌按1至9循环，风牌按东南西北循环，三元牌按白发中循环；三麻万子按一万与九万互相指示。杠后有多张指示牌时逐一展示对应宝牌，重复项保留。赤五指示牌按普通五计算，未知指示牌对应问号。此处仅计算已获得的指示牌，不推测里宝牌。

手牌按万、筒、索、字牌及点数排序，赤五紧邻普通五；收到摸牌动作后，刚摸的牌单独放在右侧，弃牌后重新理牌。排序仅影响显示，导出保留采集顺序。游戏内手动拖牌、关闭自动理牌时，排列可能与面板不同。

实时模式的自家牌河紧接自家手牌显示，保留摸切、手切、立直和已鸣标记；四家列表中不再重复显示该牌河。座位未识别时不猜测牌河归属。牌谱模式仍将各家牌河放在对应手牌下方。

面板顶部以红框显示“对手立直”，自家立直不触发此提示，多家立直会合并显示；本局结束或新局开始时清除。实时模式使用已识别或手动指定的自家座位；牌谱模式需先选择“自家”座风，提示跟随插件游标，未选时不猜测自家身份。

自家座位自动识别或手动选定后，“尚未识别”警告立即更新；若识别前已存在未追踪的动作，则提示历史手牌变化不完整，直到下一局完整开局重置。识别座位不会自动补回此前遗漏的手牌动作。

## 安装与首次核对

1. 在 Edge 地址栏打开 `edge://extensions`，开启“开发人员模式”。
2. 点击“加载解压缩的扩展”，选择 `D:\雀魂插件\extension` 文件夹。
3. 刷新雀魂页面，让采集器在游戏连接建立前加载；刷新会离开当前回放位置。
4. 重新打开牌谱，右上角应出现“牌局观察器”。可收起面板腾出画面。
5. 若成功捕获牌谱，面板自动切换到“牌谱记录”，显示四家手牌。面板的牌谱游标**独立于游戏**，通过“上一事件 / 下一事件”手动与画面对齐；当前不自动跟随游戏播放。
6. 按当前测试要求：保留你已设置的正常对局显示方式，点击游戏播放按钮后隐藏游戏工具栏，再核对。工具栏隐藏不会改变网络采集逻辑。
7. 若只看到“实时消息”，展开“采集状态”，检查连接数、接收帧、错误提示。可在练习局从开局采集增量事件。牌谱播放不一定产生实时动作消息，不能仅以画面变化判断采集器失效。
8. “导出核对记录”下载本地 JSON；可用它报告某个动作不一致的问题。

浏览器已有连接与已经下载的牌谱无法被本原型追溯读取，因此首次安装后必须刷新并重新打开。源码变更后，在扩展管理页点“重新加载”，再刷新雀魂页面。

## 核对顺序

- 开局：场风、局数、本场、立直棒、点数、剩余牌数、宝牌指示牌、手牌。
- 动作：摸牌、弃牌、摸切/手切、立直声明与成功扣点、吃碰杠、被鸣牌的弃牌。
- 牌谱牌河中的灰色牌仍按消息里的牌种读取；灰色本身不作为摸切、立直或被鸣牌的判断依据。面板分别显示“摸切 / 手切 / 立直 / 已鸣”文字。若后续增加视觉采集，须单独验证灰色牌，不得将它当作背景丢弃。
- 结算：和牌/流局及点数。
- 面板以东、南、西、北显示本局座风，随庄家轮转，并非固定屏幕方位；实时自家座位优先根据操作提示识别，也可手动选择。开局信息未获得时显示“座风待定”。事件历史保留事件发生时的座风，导出仍保留协议座位编号以便调试。未识别前，手牌增量可能不完整。
- 记录“游戏画面上的动作、面板事件编号、期望值、实际值”。若不一致，导出 JSON 即可，不需提供账号登录数据。

## 已实现与限制

- 浏览器原生 WebSocket 旁路观察；不新增游戏请求，不修改消息内容，不调用游戏出牌接口。
- 仅解码明确选取的牌局消息；登录、心跳、聊天等内容不保留。请求响应关联只保留方法名和消息序号。
- 支持 Liqi 动作混淆与明文兼容尝试，手写最小 Protobuf wire reader，无第三方运行库。
- 支持 `ActionPrototype` 中的常规开局、摸打、吃碰杠、拔北、立直成功与常规结算。
- 支持 `fetchGameRecord` 内嵌数据以及游戏随后经 fetch/XHR 下载的指定牌谱 URL。不会主动下载。支持 `GameDetailRecords.records` 与 `actions.result`。
- 仅保留规范化牌局字段，不导出账号、会话、令牌、原始二进制、下载URL或牌山。
- 断线快照暂不支持完整重建；会提示重新从开局采集。动作缺口及未知动作会标记状态不完整。
- 当前协议来自已有公开资料，必须在当前 Unity 客户端验证。特殊规则、跨版本协议、压缩/其他牌谱封装尚未适配。
- 自家手牌、牌河、副露为事件状态机推导，尚无真实对局正确率保证。最近动作座位不等于准确的下一位出牌者。
- 牌谱四家手牌仅用于复盘，不代表实时对局能读取对手暗牌。面板独立游标与游戏隐藏工具栏均不改变此边界。
- 页面内桥接消息可被同页脚本伪造，不应作为可信审计来源；桥接监听仅接收采集信息，不向页面提供密钥或任意网络请求接口。模型请求通过隔离世界中的用户面板操作发起，后台仅接受本扩展在指定游戏顶层页面发来的消息。
- 导出最多最近1000条实时事件、最近60条诊断，牌谱上限25000条/16MiB；超限会停止对应解码并提示。
