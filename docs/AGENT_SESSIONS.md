# 小局会话、只读工具与用量观测

本文描述当前源码新增功能。稳定发行版仍为 0.5.0；旧安装包不因此获得这些能力。自动化测试使用人工局面与模拟模型响应，不能证明真实服务兼容性、模型建议质量、实战牌力或费用节省。

## 开始使用

1. 加载完整版扩展，在“分析设置 → 模型设置”配置 OpenAI Chat Completions 兼容服务，并按需开启模型服务。
2. “分析上下文”默认选择“当前局面”，对应 `contextMode: snapshot`。每次使用当前授权快照，不持久保存对话；仍会保存数值用量记录。
3. 如需围绕同一小局连续讨论，可选择“本局连续会话”，对应 `contextMode: round`。它保留有界的已授权检查点、事件及手动问答，不是整场无限聊天记忆。
4. 回到牌局，开启“调用模型”。手动全局分析的“追问（可选）”可输入本次问题，例如“为什么选择这张牌，牺牲了哪些进张？”，再点击分析。问题最多 4000 字；`snapshot` 下仅携带本次问题，跨请求记忆需要 `round`。
5. “允许调用本地分析工具”默认关闭，即 `toolCalling: false`。仅在接口支持 `tools` 时启用；最终结果仍须通过 JSON 结构、合法候选、任务范围及风险证据校验。

手动全局分析与实时自动提示使用不同 lane。自动提示不携带手动问答解释历史；复盘不会因拖动游标自动请求模型。关闭“调用模型”时仍可运行本地分析，不发模型请求。会话模式与工具开关不改变数据授权范围，也不授予自动出牌能力。

## 执行预算与四个工具

| 路径 | 模型请求预算 | 工具预算 |
| --- | --- | --- |
| 默认工具关闭 | 每次最多 1 次 | 不向模型开放工具 |
| 手动全局分析／复盘，工具开启 | 每次最多 3 次，总数包含最终回答 | 最多 4 次只读调用 |
| 实时自动分析 | 每次最多 1 次 | 不开放多轮工具链 |

最后一次模型请求不再提供工具，要求模型给出最终结构化答案；预算耗尽、取消或失败不会无限重试。请求仍受超时、输出上限与单标签页并发限制。当前 Agent 每次运行的输入与输出合计预算为 131072 tokens，依赖接口报告 usage；每轮输出也受设置中的输出上限和剩余运行预算限制。缺失 usage 时只能严格限制调用次数、输出上限和时间，无法准确核算总 token。事后检测超预算不能撤销服务商已经消耗的 token。

| 工具 | 返回内容 |
| --- | --- |
| `get_current_position` | 冻结在本次分析时点的已授权当前快照 |
| `get_round_history` | 当前小局分支截至当前时点的已授权检查点与事件 |
| `compare_discards` | 本地计算的合法候选、向听与有效进张；未见枚数仍是上界 |
| `get_danger_evidence` | 公开信息推导的现物、筋、壁等证据，不提供虚构放铳概率 |

工具只读取本次冻结数据，不读取未来事件、不访问任意文件、不执行模型指定命令，也不让模型修改游戏。没有相应授权或本地计算时，工具不会补造数据。检查点由观察到的分析位置产生，不保证每次摸打都有一个检查点。

## 会话隔离、授权与本机存储

`round` 会话由场次、小局开始标识、局数与本场、数据来源、视角和自家座位、lane、接口与模型、任务、配置修订及实际授权字段共同隔离。换局、换视角、切换授权范围、任务或模型配置时，不把旧解释直接混入新会话。牌谱只使用当前游标及之前的事件；回退或同一位置出现冲突快照时建立干净分支，旧分支的未来问答不会进入当前请求。

历史仅包含用户在相应范围内已经授权给分析的字段。当前任务会独立选择常规提示词中的分析字段；小局历史与只读工具则依据实际授权快照过滤，不因隐藏某个展示分区而自动缩小已授权数据。未授权自家手牌时不能从其他页面数据补取。事件摘要仅保留受支持的公开字段和已授权自家摸牌，对手摸牌仍为未知。缩小当前授权范围会切换隔离会话；旧的已授权数据可能仍留在有界本地存储，直到淘汰或用户清除，不会因为切换模式立即抹除。

本地会话通过扩展 `chrome.storage.local` 的受信上下文存储保留，默认预算如下：

| 资源 | 默认上限 |
| --- | --- |
| 会话总数 | 12 |
| 每会话检查点 | 8 |
| 每会话手动问答 | 6 |
| 每会话事件摘要 | 64 |
| 会话总存储预算 | 2 MB（2,000,000 字节的保守估算预算） |

超出预算时淘汰旧数据，历史不会无限增长。worker 休眠或重启后可从本机恢复有稳定身份的会话；游戏页面刷新后，如果无法可靠恢复场次与小局身份，使用新的隔离会话，不按相似手牌猜测匹配旧局。`snapshot` 模式不新增持久对话。保存、切换或清除模型配置会取消在途请求并清空小局会话；数值用量记录保留，便于比较切换前后两种模式。

会话包含已授权牌局信息、手动问题及经校验的模型答案，因此与只含数值的用量日志不同。选择 `round` 后，历史会按当前任务的授权边界发送给你配置的模型服务。数据处理仍由该服务负责；本项目没有中转服务器或遥测上传。

## Pi 与现有架构

完整版使用真实上游 `@earendil-works/pi-agent-core` 和 `@earendil-works/pi-ai` 1.4.0 的轻量 Agent loop，在 MV3 worker 中运行。`extension/pi-runtime.js` 是提交到仓库的浏览器 bundle，适配代码位于 `scripts/pi-runtime-entry.mjs` 等文件；没有在扩展中运行 Node.js、完整 Pi 编码助手或终端进程。

`extension/agent.js` 准备任务、冻结输入并提供只读工具；原有 harness 保留有界步骤、取消和轨迹。`round-context.js` 管理小局身份、分支与本机历史，`model-session-transport.js` 把消息和工具映射到已有 Chat Completions 请求。网络、权限及 API Key 继续由 `background.js` 管理。`model-usage.js` 只归一化数值，`agent-run-store.js` 保存有界运行记录。

Pi 上游拥有更广的模型适配能力，但本扩展当前仅接入已有 OpenAI-compatible transport，不因此获得所有提供商原生 SDK 或原生 Anthropic、Gemini、Responses 协议。其他协议仍须兼容网关。DeepSeek 思考模式的工具中间轮会按接口要求，在同一次运行中回传 `reasoning_content`；不把该字段写入持久会话或用量记录。DeepSeek Harness 是设计参考，不是新增 SDK 或运行依赖。

## 稳定前缀不等于不用重传

模型规则、任务说明与静态 JSON Schema 放在 system 消息前部；同一任务跨局面保持稳定。动态的合法弃牌、风险候选和对手座位放入当前快照的 `outputConstraints`；最终仍由本地解析器强校验，不能用缓存替代合法性判断。

这有助于服务商识别重复前缀，但 Chat Completions 是无状态请求：本扩展仍在每次请求中发送所需上下文及有限历史，没有使用远端 `previous_response_id` 之类的会话引用协议。

- **网络字节**：取决于实际请求体；本地保留历史不会让历史自动免传。
- **服务端缓存**：取决于服务商、模型、前缀、缓存时效与路由；前缀相同也不保证命中。
- **计费**：取决于返回的缓存用量与所配置价格；`round` 可能因为额外历史或工具回合增加费用。

因此不承诺更低网络流量、缓存命中率或省钱效果。比较模式时应使用相同服务、模型与相近任务，检查实际 usage，而不是仅比较请求次数。

## 用量、未知值与费用估算

分析结果可展开“用量与费用”。`inputTokens` 包含缓存读取和写入；`uncachedInputTokens` 表示未缓存输入。`reasoningTokens` 是输出的一部分，计算费用时不再额外加一次。

只提取服务实际返回的有限非负数值；未返回的计数保持 `null`。无法确定缓存读取量时，不假装它为零，未缓存输入及相关费用也可能未知。OpenAI 兼容协议没有单独的适用缓存写入计数时，该项可为零；其他协议的数值归一化支持不表示已经接通对应原生传输。

多次模型请求按字段汇总。若某次请求失败、响应不可读或 usage 缺失，该次可能仍被计费；无法确认的汇总保持未知，不把前几次已知用量冒充完整总量。取消不代表服务商一定未计费。

设置页可选填写币种，以及每百万 token 的未缓存输入、输出、缓存读取、缓存写入价格。价格允许零和小数，必须非负；空白表示未知。只按填写价格估算，不查询服务商价目、不换汇、不把估算当作账单。没有相应适用价格或用量时，总费用为 `null`。

设置页“导出用量记录”读取最近最多 100 条本机运行记录，下载 `mj-agent-usage-v1` JSON；它包含导出时间、运行时间、状态、snapshot/round 模式、lane、调用次数、耗时、数值 usage 和费用。未知值原样保留，不上传。用量记录不含完整 prompt、牌局正文、问题、回答、API Key 或接口地址。

“清除本地会话和运行用量”会取消在途运行并清理会话与数值记录，保留服务配置；“清除配置”也清除这些数据及配置和密钥。清理不能撤销已经发送给服务商的请求。数据键分别是 `agentRoundContextV1`、`agentRunsV1`，受信设置页通过后台消息执行查询和清理。

## 开发与验证

开发、检查与构建使用 Node.js 22.19+：

```sh
npm ci
npm run pi:bundle
npm run check
npm test
npm run build
```

仅加载已提交的 `extension/` 或已构建目录无需安装 Node.js。更新上游或 MV3 适配后重新生成 bundle，并核对两个 profile 的依赖边界；独立获取器不包含 Pi、模型会话或模型权限。单测覆盖预算、取消、历史隔离、部分失败、数值持久化和消息边界，仍不能替代真实客户端与真实模型验证。
