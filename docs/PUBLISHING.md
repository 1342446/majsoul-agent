# 公开与打包

公开准备不等于已经发布。本文件只描述可以复现的操作；运行打包脚本不会提交、推送、创建仓库或修改可见性。

## 当前建议

早期私密原型使用过游戏截图牌面，旧Git提交和旧ZIP仍可能包含这些素材；Git作者邮箱也会随历史公开。仅删除最新工作树中的图片或加入 `.gitignore` 不能清除历史。

建议使用当前整理后的**干净源码快照**作为新公开仓库的初始内容，保留原私密仓库用于恢复和研究。直接将旧仓库改为public会公开旧历史，不推荐。若必须沿用仓库名称，应先确定私密仓库迁移方案；不要在未确认时强推或重写历史。仅强推一个新分支也不能保证旧提交或远程缓存已经清除。

## 本地检查和打包

```sh
npm run check
npm test
python scripts/package-public.py
```

检查与测试只需Node.js 22+；打包脚本需Python 3.10+，只使用标准库。

私密开发区还有并行功能未完成时，可以明确指定已提交的基础版本，只从该版本读取运行代码和测试，再加入本次原创牌面、发布文档及检查脚本：

```sh
python scripts/package-public.py --base-ref de1c403 --snapshot-version 0.2.1
```

本次公开准备使用上述基础版本。打包器会在独立临时目录中实际运行对应代码的检查和全部测试，不将工作区未完成的新模型逻辑混入包。准备包中的测试数量可能少于正在开发的工作区；两者不能混为一谈。

脚本按明确的文件／目录白名单生成：

- `dist/majsoul-observer-source-0.2.1.zip`：干净源码，解压后为 `majsoul-observer/`，包括源码、原创牌面、人工测试、文档与CI。
- `dist/majsoul-observer-0.2.1.zip`：解压即可加载的扩展目录，包含MIT许可证和来源说明。
- `dist/SHA256SUMS-0.2.1.txt`：上述文件的SHA-256。

排除 `.git`、`research/`、旧版ZIP、真实日志、原始HAR和浏览器配置；检测部分常见凭据格式。白名单和模式扫描不能代替人工审查。不要从整个私密仓库直接创建GitHub源码包作为本次公开包。

## 公开前最后确认

1. 确认使用MIT许可证，检查原创SVG与来源说明；不要将旧截图或其ZIP放回公开快照。
2. 以干净源码初始化新仓库。首次提交前配置GitHub提供的noreply邮箱，避免使用个人邮箱；不要复制旧 `.git` 目录。
3. 确认README截图仅为人工离线演示，没有账号、模型凭据或真实牌局信息。
4. 确认公开的目标仓库及名称，再创建或切换可见性、推送首次提交。本任务要求为“准备公开”，这些外部动作须由维护者明确决定。
5. 在GitHub开启Private vulnerability reporting，核对Issue模板和Actions权限。仓库创建后实际运行CI；本地检查不能宣称远程CI已经通过。
6. 为0.2.1创建Release，上传本次专用扩展ZIP和校验文件。不要上传旧原型包。打包文件没有签名，也不是Chrome或Edge商店分发包。

公开后的仓库简介可使用：

> 雀魂网页版牌局观察器：可拖动面板、本地整场结算记录，以及用户自选大模型分析。Manifest V3，无遥测，模型默认关闭。

建议Topics：`mahjong`、`majsoul`、`browser-extension`、`chrome-extension`、`llm`、`replay`。

## 仍需实测的范围

当前Unity客户端真实整场采集、断线续接、Chrome独立安装、具体模型服务和建议质量仍待验证。不要将人工协议测试、离线界面截图或本地CI等同于这些能力已被证实。
